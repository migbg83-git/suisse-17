## Finding 2: Architecture Issue — Multiple Metadata Sources (MEDIUM PRIORITY)

### Summary
**Three parallel metadata systems identified, not synchronized:**

#### Source 1: Central Bundle (PRIMARY)
- **Location**: `src/assets/content/articles.json`
- **State**: 22 articles in single JSON array
- **Generated by**: `scripts/build-content.ts` (build process)
- **Schema**: 
  ```json
  {
    title, slug, description, summary,
    category: { slug, name },
    tags: [{ slug, name }],
    author, date, readingTime, featured,
    relatedArticles: [slugs],
    content, html
  }
  ```

#### Source 2: Individual Slug-Named Files
- **Location**: `src/assets/content/articles/*.json` (24 files)
- **State**: Using slug as filename
- **Schema**: Varies; some missing fields
- **Examples**: `organizational-memory-activo-ai-native.json`, `context-engineering-vs-prompt-engineering.json`
- **Issue**: 24 files vs 22 articles (2 appear to be variants)

#### Source 3: Source Markdown Metadata
- **Location**: `content/enterprise-ai/article-NN/article.json` (22 files)
- **State**: Source-of-truth before build
- **Schema** (DIFFERENT from articles.json):
  ```json
  {
    title, slug, description, excerpt,
    category (string, not object),
    tags (string array, not objects),
    keywords (array),
    readingTime, difficulty,
    featured, published (boolean),
    author, relatedArticles (slugs),
    canonicalUrl, ogImage
  }
  ```

### Divergence Detected

| Field | articles.json | article-NN/article.json | Conflict? |
|-------|---|---|---|
| category | `{slug, name}` object | `string` | ❌ YES |
| tags | `[{slug, name}]` objects | `[string]` array | ❌ YES |
| summary | present | absent (has `excerpt`) | ❌ PARTIAL |
| keywords | absent | present | ⚠️ Asymmetric |
| difficulty | absent | present (e.g., "advanced") | ⚠️ Asymmetric |
| published | absent | present (boolean) | ⚠️ Asymmetric |
| canonicalUrl | absent | present | ⚠️ Asymmetric |
| date | present | present | ✅ Consistent |
| author | present | present | ✅ Consistent |

### Impact
- **Data Consistency Risk**: If sources diverge during updates, which is authoritative?
- **Integration Hazard**: External systems consuming articles.json may break if schema changes
- **Maintenance Burden**: Three sources to keep in sync

### Evidence
Example comparison for "Organizational Memory" article:

**In articles.json** → has 8 tags as objects: `[{slug: "enterprise-ai", name: "Enterprise AI"}, ...]`

**In article-01/article.json** → has 8 tags as objects matching above (good)

**In articles/organizational-memory-activo-ai-native.json** → has 8 tags as objects (good)

BUT in `articles/context-engineering-vs-prompt-engineering.json`:
```json
"category": "Context Engineering",  // String, not object!
"relatedArticles": []  // Empty here too
```

### Root Cause
The build pipeline (`scripts/build-content.ts`) normalizes article-NN/article.json into articles.json, but:
- Individual `.json` files in `articles/` appear to be manually maintained (not generated)
- Inconsistent update discipline across the three sources
